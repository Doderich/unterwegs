# Home and collection navigation

The app opens on a Home feed, with Collections, Places and World as its other app-level destinations. Opening a collection pushes a separate workspace. On iOS its tabs are Plan, Map, Stays, Notes and a detached native Search button; Plan combines a day view and all-days overview through a native segmented picker. Android has Plan, Map, Stays and Notes, with search in the header; Plan switches between day view and all-days overview using a native Material segmented control at the top. The app bar and collection bar are never shown together. Back returns to the previous app destination.

The existing native grouped lists, system typography, terracotta accent, photo treatment and accessibility settings remain the visual system. This is an extension of the existing interface, not a new visual identity.

Home prioritises current collections and today's visits, then interleaves upcoming collections and scheduled visits by date. A compact cover card can feature the first collection, without repeating it in the list. Recently saved places follow the dated feed; saving a place alone does not invent a visit. Invitations lead to Collections for acceptance or decline. Compact headers keep creation and settings accessible. On iOS, app-wide Search sits separately at the bottom right of the native tab bar and expands into the system search field; Android keeps search in the header.

Places is the user's persistent location library, including places outside any collection. Creation does not require a collection. Visits can be scheduled separately, and existing places can be added to a collection without replacing their other memberships. Opening a place caches its metadata and downloads its photos/attachments through the same persistent file cache as collections.

Search uses the system search field on iOS and opens globally from the app level and scoped to the current collection from the collection workspace. Collection search stays inside that collection and shows its contents, without offering global scope or returning the collection itself. Global results include standalone places and deduplicate locations also present in loaded collections. Offline results use the persisted data and explain missing unopened collections.

Dates follow visit time zones; server all-day visits keep their calendar dates. Collection summaries have date-only bounds and initially use the phone's calendar until full collection data supplies its own zone. Every write remains online-only. Collection reading still comes from one collection response; the location library uses its own verified endpoint.

Verification: live library pagination, collection-free create/read/edit, scheduled visits, later collection membership and cleanup passed on temporary data. Automated tests cover library requests, date boundaries, duplicate search results, schema compatibility and translations. Device checks and limits are recorded in ROADMAP.md.

Search control policy: all iOS search, including Places list filtering, must use the system search control, never a plain input inside a card. Android uses a top Places search launcher and a dedicated Material-style search view, entered from the list or top app-bar magnifier. The view has native text entry, live results, Back and Clear; Places carries its selected library filter into that view. List filtering, collection search and global search retain their own fixed scopes. See [DESIGN.md](../DESIGN.md#search-platform-controls-and-scope) for interaction details and implementation gaps.
